# Take Phone

Интернет-магазин техники в Тюмени: публичный каталог iPhone, оформление заявки
без онлайн-оплаты и закрытая панель сотрудника с закупочными ценами.

Стек: vinext (Next.js App Router на Vite) + React 19 + Tailwind CSS v4,
деплой на Cloudflare Workers.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production-сборка
npm run lint
npm run typecheck
npm test           # 67 тестов доменной логики и закрытых маршрутов
```

Панель сотрудника — `/staff`. Локально пароль `takephone`; в production он
запрещён, см. раздел «Панель сотрудника».

---

## Что видит покупатель и что видит сотрудник

Публичная часть содержит только бренд Take Phone, конечную цену и наличие.
Названия поставщиков, закупочные цены и логика выбора источника **не попадают
в браузер**: они живут в серверном слое и отдаются исключительно из
`/api/staff/*` за проверкой сессии.

Разделение обеспечено на уровне типов:

- `CatalogProduct` — публичная модель, в ней нет поля `source`;
- `SourceOffer` — предложение поставщика, остаётся на сервере;
- `toPublicProducts()` в `lib/catalog/aggregate.ts` — единственный переход
  из внутренней модели в публичную.

### Склейка дублей

Товары от разных поставщиков сравниваются не по названию, а по
нормализованному ключу:

```
brand + model + memory + color + SIM
```

Например, `Apple iPhone 17 Pro Max 256GB Deep Blue`,
`iPhone 17 Pro Max 256 ГБ тёмно-синий` и
`Смартфон Apple iPhone 17 Pro Max 256Gb Deep Blue (eSIM)` дают один
`matchKey` и один товар в каталоге. Цвета приводятся к канонической форме со
свёрткой регистра, `ё`/`е` и разделителей, иначе одно устройство разъезжается
на две карточки.

Исходные предложения сохраняются отдельно от публичного товара — панель
сотрудника показывает их все.

### Позиции каталога и тип SIM

`matchKey` включает тип SIM, а `slug` — нет: он строится из модели, памяти и
цвета. Раньше из-за этого версии eSIM и «две nano-SIM» попадали в каталог
двумя внешне одинаковыми карточками с общим адресом.

Теперь варианты собираются в одну позицию (`buildListings`):

- в каталоге одна карточка на модель + память + цвет, цена показывается «от»;
- тип SIM выбирается на странице товара, вместе с ним меняются цена и наличие;
- в заявку попадает конкретный вариант — сотрудник видит его в составе заказа;
- в панели сотрудника варианты по-прежнему показаны отдельными строками.

### Наценка

Приоритет: **товар → модель → категория → глобальная**.
Если специального правила нет, применяется глобальная наценка 5 000 ₽.

```
конечная цена = минимальная закупочная цена среди предложений в наличии
              + применённая наценка
```

Если в наличии нет ни одного предложения, берётся минимальная цена среди
позиций «под заказ». Для статуса «Под заказ» из цены вычитается 1 000 ₽.
При оплате картой итог умножается на 1,135.

Уровень применённого правила показывается в панели сотрудника, поэтому всегда
видно, откуда взялась цена.

## Автоматический каталог

`SourceAdapter` (`lib/sources/adapter.ts`) описывает контракт источника:
`fetchProducts()`, `normalizeProduct()`, `getAvailability()`, `getPrice()`,
`getImages()`, `getLastSyncStatus()`. Общая нормализация реализована в
`BaseSourceAdapter`, каждый источник описывает только то, откуда приходят
строки и как называются его поля.

Режимы работы задаются переменной `CATALOG_MODE`:

- **`fixtures`** (по умолчанию) — читается демонстрационный набор из
  `lib/sources/fixtures/`. Панель сотрудника помечает это как «Демо-данные».
- **`live`** — адаптер читает согласованный прайс-лист по адресу из
  `SOURCE_*_FEED_URL`. Если адрес не задан, источник возвращает ошибку и она
  видна в журнале синхронизации. Подмены реальных данных демонстрационными
  не происходит никогда.

### Почему прямой сбор данных не реализован

Проверка трёх сайтов на 28 августа 2026:

| Источник | Движок | robots.txt | Прайс-лист (YML/CSV) |
| --- | --- | --- | --- |
| first-apple72.ru | 1C-Bitrix | закрыты служебные разделы, каталог открыт | не найден |
| iceapple.ru | OpenCart | закрыты поиск и пагинация, есть `sitemap.xml` | не найден |
| phone24.ru | 1C-Bitrix | `Crawl-delay: 20`, закрыты адреса с query | не найден |

Технически страницы отдаются сервером и разбираются, но регулярный парсинг
чужого каталога — это вопрос не техники, а договорённости: у сайтов нет
публичного фида, а условия использования сбор данных не разрешают. Поэтому
парсер не написан. Вместо него подготовлен импорт по согласованному каналу.

### Что нужно запросить у владельцев сайтов

1. Письменное разрешение на использование остатков и цен.
2. Выгрузку прайс-листа: YML (Bitrix и OpenCart умеют это из коробки), CSV
   или JSON-эндпоинт.
3. Периодичность обновления файла и, желательно, поле «время обновления».
4. Обязательные поля: внешний идентификатор, название, объём памяти, цвет,
   тип SIM, закупочная цена, статус наличия, ссылка на карточку.
5. Токен или IP-ограничение, если фид не должен быть публичным.

Как только фид появится, достаточно задать `CATALOG_MODE=live` и
`SOURCE_*_FEED_URL` — код адаптеров менять не нужно.

## Хранилище

Данные лежат в **Cloudflare D1**. Биндинг объявлен в `.openai/hosting.json`
(`"d1": "DB"`), его читает `vite.config.ts`; в коде база доступна через
`import { env } from 'cloudflare:workers'`.

Выбор реализации — в `lib/repositories/index.ts`:

| Условие | Хранилище | Что с данными |
| --- | --- | --- |
| биндинг D1 доступен | `D1CatalogRepository` | переживают перезапуск |
| биндинга нет | `MemoryCatalogRepository` | живут до перезапуска процесса |

Текущее хранилище видно в панели сотрудника — плашка «База D1» или
«Память процесса».

### Таблицы

`migrations/0001_initial.sql`:

- `orders` — заявка: номер, контакты, способ получения и оплаты, суммы,
  предоплата, статус, комментарий сотрудника;
- `order_items` — позиции: модель, память, цвет, тип SIM, цена, количество;
- `order_status_events` — история смены статусов;
- `markup_rules` — наценки всех уровней;
- `sync_runs` — журнал синхронизаций;
- `source_offers` — сырые предложения поставщиков (закрытые данные).

Применение миграций:

```bash
npx wrangler d1 migrations apply take-phone --local
npx wrangler d1 migrations apply take-phone --remote
```

`ensureSchema()` в `lib/repositories/d1.ts` выполняет ту же DDL идемпотентно
при первом обращении, поэтому демо поднимается и без ручного запуска миграций.
Для рабочего стенда миграции всё равно стоит применить явно.

## Заявки

`POST /api/orders` проверяет данные на сервере (имя, телефон, согласие на
обработку данных, способ получения и оплаты, состав заявки), считает суммы
заново — клиентским числам не доверяем — и сохраняет заявку в базу.

Каждая заявка получает номер вида `TP-260829-M1L9`: дату видно сразу,
хвост различает заявки одного дня.

Статусы: Новая → В работе → Связались с клиентом → Подтверждена → Завершена,
плюс Отменена. Каждая смена пишется в историю.

Внешний канал уведомлений подключается переменными окружения:

1. Telegram, если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`;
2. иначе `ORDER_WEBHOOK_URL`, если он задан;
3. иначе никуда — заявка остаётся в базе с пометкой `stored`, и покупателю
   так и пишут: «Заявка сохранена и уже доступна сотруднику в панели».
   Про отправку в Telegram при неподключённой интеграции не говорится.

Онлайн-оплата не проводится. Предоплата 10 000 ₽ за бронирование при
самовывозе описана как условие, которое согласует менеджер, а не как
списанная сумма.

## Панель сотрудника

`/staff`, вход по паролю, сессия — httpOnly cookie, подписанная HMAC-SHA256,
срок 12 часов. Страница закрыта от индексации, `/staff` и `/api/` запрещены
в `public/robots.txt`.

Три режима доступа (`getStaffAuthMode` в `lib/server/auth.ts`):

| Режим | Когда | Поведение |
| --- | --- | --- |
| `configured` | заданы `STAFF_PASSWORD` и `STAFF_SESSION_SECRET` | рабочий вход |
| `demo` | секретов нет, но `NODE_ENV != production` или `ALLOW_DEMO_STAFF_ACCESS=1` | пароль `takephone` + предупреждение в интерфейсе |
| `misconfigured` | секретов нет в production | панель не открывается, показывается ошибка конфигурации |

Пароль `takephone` в production не принимается.

### Разделы

**Заявки.** Счётчики новых, в работе, завершённых, заявок за сегодня и суммы
новых. Список с поиском по номеру, имени и телефону, фильтром по статусу и
сортировкой по дате; новые заявки выделены. В карточке заявки — контакты
с кнопками «позвонить», «скопировать» и Telegram, состав с памятью, цветом и
типом SIM, расчёт с комиссией карты, предоплата, комментарий клиента, история
статусов и поле внутреннего комментария.

**Каталог и поставщики.** По каждому варианту: предложения всех трёх
источников с закупочной ценой, наличием, временем обновления и ссылкой на
исходную карточку; минимальная закупка; выбранный поставщик; наценка с
указанием уровня правила; конечная цена. Наценку можно менять для товара,
модели и глобально.

**Синхронизация.** Состояние трёх источников, режим (`Демо-данные` или
`Прайс-лист`), время обновления, количество позиций, ошибки, кнопка ручного
запуска и история последних запусков. Текущее хранилище тоже показано здесь.

## Изображения

Используются официальные пресс-фотографии Apple, сохранённые локально в

## Витрина-превью на GitHub Pages

Публичная часть собирается в статику для показа клиенту:

    STATIC_BASE_PATH=take-phone node scripts/build-static-preview.mjs

Результат — `dist/client`, он публикуется в ветку `gh-pages`:
**https://artemdiscipline.github.io/take-phone/**

Что в превью есть: главная, каталог с фильтрами и поиском, карточки товаров,
корзина-заявка с пересчётом при оплате картой, страницы сервиса, доставки и
контактов.

Чего нет и почему: `/api/*` и `/staff` из сборки исключаются. Pages отдаёт
только статику, а переносить панель сотрудника на клиент нельзя — это выложило
бы закупочные цены и поставщиков в открытый доступ. Форма заявки открыта
целиком, но при отправке честно сообщает, что заявки со статической витрины не
уходят, и предлагает телефон и Telegram. Метка свежести показывает дату сборки,
а не «N минут назад»: страница собрана заранее, и относительное время было бы
неправдой.

### Про подпапку

vinext 1.0.0-beta.5 не поддерживает `basePath` в статическом экспорте:
в `dist/build/prerender.js` он не упоминается, и пререндер отвечает 404 на
каждый маршрут. Поэтому префикс подпапки проставляется в исходниках —
`withBase()` из `lib/build-mode.ts` и компонент `AppLink`, — а не
постобработкой готовой сборки. В режиме превью `AppLink` рендерит обычную
`<a>`: клиентский роутер Next всё равно не знает о подпапке.

Статику Next раскладывает `assetPrefix`; он же складывает её в
`dist/client/<префикс>/_next`, поэтому скрипт сборки поднимает содержимое на
уровень выше и кладёт `.nojekyll`.

### Обновить превью

    STATIC_BASE_PATH=take-phone node scripts/build-static-preview.mjs
    # затем опубликовать содержимое dist/client в ветку gh-pages

Автосборку через GitHub Actions можно добавить файлом
`.github/workflows/pages.yml` — для этого нужен токен со scope `workflow`.

## Что ещё требует подтверждения владельца

- **Комиссия по карте 13,5 %.** Значение названо в переписке и вынесено в
  `CARD_PAYMENT_FEE_RATE`; документального подтверждения пока нет.
- **Обработка персональных данных.** Страница `/privacy` — черновик: в ней
  описано только фактическое поведение формы. Нужны реквизиты оператора,
  адрес для обращений, срок хранения заявок, перечень третьих лиц и текст
  согласия в редакции юриста.
- **Условия гарантии** по конкретным моделям.
- **Стоимость и сроки доставки** по Тюмени.
- **Точка на карте** для раздела «Контакты».
- **Предоплата 10 000 ₽** — подтвердить формулировку и случаи, когда она
  действительно требуется.

Telegram разделён: канал `@Takephone72` в подвале и разделе «Мы в сети»,
менеджер `@take_phone72` в шапке, на карточке товара и в заявке.
